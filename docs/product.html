Enterprise Change Graph

Start with a concrete change and answer the questions a release team actually has: what can be affected, why, what must be tested, who should review it, what is excluded, and whether policy allows the release.

No opaque risk score is required. An impacted object has a path; an excluded object can have an explainable barrier.

Why it exists

Enterprise change is rarely isolated to the object being edited. The expensive part is reconstructing the surrounding blast radius quickly enough to test and review the right things.

01

Explain impact

Typed propagation produces deterministic paths across processes, systems, data, mappings, interfaces, controls, tests, and owners.

02

Explain non-impact

why-not identifies direction, filters, depth limits, or physical disconnection instead of leaving exclusions implicit.

03

Turn scope into a gate

Regression gaps, ownership gaps, removal-aware review, release collisions, and policy checks turn analysis into a concrete release decision surface.

Impact should be inspectable

The graph can be composed from artifacts teams already maintain, so change analysis does not require manually recreating the landscape in another CMDB.

Quick loop

ecg validate examples/customer-country-change.yaml
ecg impact examples/customer-country-change.yaml \
  --change CR-142 --explain
ecg report examples/customer-country-change.yaml --change CR-142
ecg gate examples/customer-country-change.yaml \
  --change CR-142 --policy policies/baseline.yaml

Beyond a single change

Compose graph fragments, import as-code contracts and API specs, ingest JUnit evidence, detect release collisions, compare predicted impact with observed results, and export GraphML/Cypher or a static explorer.

Not a manually maintained CMDB and not an AI risk scorer. The core is deterministic and evidence-first; LLMs are optional consumers of compact graph context.

Where it connects

Enterprise Change Graph is intentionally broader than Transformation Graph: it begins with a change/release question and follows impact into review, regression, ownership, and release governance.
